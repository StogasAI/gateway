# Stogas redaction

This package is a fixed step in the Stogas request path. It has no loader, manifest, activation control, external service, or retained replacement map.

After catalog routing filters, it scans accepted Chat Completions and Responses text containers, including stop sequences, before token estimation and provider conversion. It uses typed irreversible placeholders for explicitly selected detectors. Context is required for ambiguous number formats. Built-in detectors exclude inferred names, street addresses, locations, UUIDs, ordinary dates, and unformatted numbers to limit false positives. Provider-signed Chat reasoning details and top-level encrypted Responses reasoning items are preserved only in their accepted replay locations.

Saved policies use `plugins.stogasRedaction`: nine optional preset flags, literal rules, and one optional `customPattern` per scope. Applicable requirements combine; a permitted request policy can add redaction. A child's false or omitted option cannot remove a parent's requirement. Only explicitly configured rules run; with no configured scope, text stays unchanged. The [policy reference](https://stogas.ai/docs/plugins/pii-redaction) lists every identifier covered by each preset and synthetic test examples.

The reusable library uses the same nine presets through `Options.Patterns`: `email_address`, `phone_number`, `social_security_number`, `credit_card_number`, `ip_address`, `api_keys_and_secrets`, `bank_identifiers`, `national_identifiers`, and `health_identifiers`. They map directly to disjoint masks covering all 43 built-in entity types. SSNs and payment cards stay separate from national and bank identifiers. An empty list disables built-ins. `NewWithPolicy(nil)` leaves text unchanged. Detection never verifies credentials or contacts their issuer.

Each unique custom expression has its own leftmost-longest RE2 matcher. All expressions scan the original text; overlapping intervals merge before replacement with `<CUSTOM_PII>`. Within one expression, matching is non-overlapping. Client-supplied placeholders do not exempt surrounding matches or supply built-in context labels. Replacements can move real labels into range or create new custom matches on a later call, so universal idempotence is not promised.

Custom matching uses anchored standard-library matchers over a metered `io.RuneReader`. A preceding real rune preserves boundary and anchor semantics away from offset zero. Candidate filtering skips impossible starting characters. Every read, including repeated lookahead, spends the shared request budget; exhaustion discards the result even if the engine reports a match at the reader's artificial EOF. No background matching continues after rejection. Unbounded repetitions remain supported.

Library bounds are 16 expressions, 512 bytes per expression, 4,096 total expression bytes, and 4,096 total compiled instructions. Saved policies restrict this to one expression per scope and three combined. Empty, zero-width, invalid, overly complex, and placeholder-matching expressions are rejected without echoing them. Person names and street addresses need a separately measured contextual detector.

The clean path returns the original bytes. Custom matching and variable secret lookahead share 67,108,864 weighted work units per request, across fields and expressions. This limits computation, not wall-clock time. Nesting and match counts are separately bounded. Numeric candidates recognize Unicode decimal digits, spaces, and common hyphens without normalizing the whole prompt; email candidates include Unicode letters and combining marks. Configured redaction produces `plugins.stogas_structured_pii_redaction.items_redacted` and `duration_us`, including zero matches. With no configured rules, `Summary()` returns nil and the log omits the plugin entry. Synthetic logs also omit unproven execution. Source values, hashes, offsets, replacement maps, and per-category counts are never logged. Category counts would reveal facts about prompt contents outside the guest.

The independent Go implementation and its positive and negative tests were checked against the Apache-2.0 [Microsoft Presidio](https://github.com/microsoft/presidio/tree/eb93051b60b7daa44b4b8b1acdcce60522bacc8a), [Censgate redact](https://github.com/censgate/redact/tree/f45c45ccaab17b2c1801a64b4c67cc5cf7188a5e), and [detect-secrets](https://github.com/Yelp/detect-secrets/tree/5e141933554a0b74e7341841f318be21e895339c) corpora; the MIT-licensed [Gitleaks](https://github.com/gitleaks/gitleaks/tree/b58d3f102cf3a2c84cb7f923d05c25c9b1aed84b) and [Braintree card-type](https://github.com/braintree/credit-card-type/tree/fbd8ed80a411fa9b238055208c19a7323cd38e21) corpora; [Google libphonenumber](https://github.com/google/libphonenumber/tree/dba03901d523cc358310859a3d3c34d11b92f0bf) calling codes; and the [SWIFT IBAN Registry release 101](https://www.swift.com/sites/default/files/files/iban-registry-v101.pdf). No source code was imported.
